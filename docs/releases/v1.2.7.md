# OpenCode Usage Monitor v1.2.7

This release focuses on reducing Windows taskbar/Explorer freeze risk and keeping the OpenCode fork maintainable.

## Fixed

- **Explorer responsiveness:** replace synchronous `SHAppBarMessage(ABM_GETTASKBARPOS)` position lookups with taskbar-window bounds so the monitor avoids waiting for an unresponsive shell.
- **Usage-poll concurrency:** avoid holding the global application-state mutex while waiting for provider I/O, and prevent overlapping refresh requests from creating uncontrolled concurrent polls.
- **Taskbar event handling:** defer tray repositioning to the UI message loop and keep window movement outside the global state lock.
- **OpenCode rolling usage:** count five-hour usage correctly across local month boundaries, without changing daily or monthly totals (PR #1).
- Resolve three Rust Clippy warnings exposed by a newer compiler.

## Maintenance

- Add a Windows CI pipeline covering formatting, Clippy, tests, and a release build.
- Add weekly Dependabot update proposals for Rust crates and GitHub Actions.
- Correct this fork's GitHub repository metadata for release checking.
- Remove an obsolete upstream executable from source control.
- Publish a SHA-256 checksum alongside the Windows executable.

## Installation

Download `opencode-usage-monitor.exe` below and run it on Windows 10/11. This is a portable executable; no installer is required.

For existing users, exit the old instance before replacing the executable. Settings in `%APPDATA%\OpencodeUsageMonitor\` are preserved.

**Important:** This fork's release binaries are not Authenticode-signed by the original upstream publisher. The built-in self-updater still requires that trusted signature, so use **manual download/install** for this release. No certificate or security checks have been bypassed. This fork does not yet have a registered WinGet package.

## Testing and known limitations

Windows GitHub Actions runs formatting, lint, unit tests, packaging, and Release compilation before publishing. **An actual Windows Explorer restart, long-duration memory/GDI-handle soak test, and managed corporate-PC compatibility test have not been performed for this release.** The changes address specific lock contention and cross-process blocking risks, but do not establish that every previous Explorer crash is fixed.

If you observe a hang, start the executable with `--diagnose` and include the relevant diagnostic logs and Windows Event Viewer details in a GitHub issue. Do not share credentials or personal OpenCode project contents in bug reports.
